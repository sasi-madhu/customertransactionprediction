# 🏦 Customer Transaction Prediction
### Project Code: PRCP-1003 | Domain: Banking

---

## 📌 Project Overview

This project builds a machine learning model to predict **which bank customers will make a transaction in the future**, regardless of the transaction amount.

- `target = 1` → Customer **WILL** make a transaction
- `target = 0` → Customer **WILL NOT** make a transaction

## 🤖 Models Used & Why

### 1. Logistic Regression 🔵
- **Why:** Simple baseline model. Fast to train and easy to understand. Good starting point.
- **Handles imbalance:** `class_weight='balanced'`

### 2. Random Forest 🟢
- **Why:** Powerful ensemble — builds 100 trees and takes a vote. Handles many features well.
- **Handles imbalance:** `class_weight='balanced'`

### 3. Gradient Boosting 🟠
- **Why:** Learns from mistakes step by step. Often best for tabular banking data.
- **Handles imbalance:** `compute_sample_weight`

---

## 📊 Key Challenge: Class Imbalance

The dataset is **imbalanced**:
- ~90% of rows → `target = 0` (No transaction)
- ~10% of rows → `target = 1` (Will transact)

This is why we:
- Used `class_weight='balanced'` in models
- Used `stratify=y` in train-test split
- Used **ROC-AUC** as primary metric (not just accuracy)

---

## 🏆 Best Model

Based on **ROC-AUC score**, **Gradient Boosting** is recommended for production.

> ROC-AUC is preferred over accuracy because accuracy is misleading on imbalanced datasets.
> A model that always predicts "No Transaction" would get 90% accuracy — but zero usefulness!
